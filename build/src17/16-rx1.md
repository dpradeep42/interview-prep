The fix is the effect's cleanup function. React runs the cleanup before running the effect again, and when the component unmounts. And you can use it two ways.

One is an ignore flag. Inside the effect, declare let ignore equals false, and in the cleanup, set ignore to true. When the response arrives, only update state if ignore is still false. The stale response just gets thrown away.

The other is AbortController, which I prefer. Create a controller in the effect, pass controller.signal to fetch, or to axios through its signal option, and call abort in the cleanup. The cleanup also stops you setting state after unmount.

Honestly though, in real apps I avoid hand-written fetching in effects. Libraries like TanStack Query or RTK Query handle caching, deduplication, race conditions, retries and loading states for you, keyed by the query parameters. Effects are better kept for syncing with external systems.
