### ngx | How do you poll an API with RxJS and stop when the job is done? | polling rxjs, poll api until complete, interval switchmap, takewhile polling, rxjs timer polling

Alternatives: for many users or frequent updates, server push with SignalR or Server-Sent Events is more efficient than polling. But for occasional long-running jobs, polling is simple, reliable and works through all proxies.

### ngx | debounceTime vs throttleTime vs auditTime vs sampleTime in RxJS: what is the difference? | debouncetime vs throttletime, audittime, sampletime, rate limiting rxjs operators, rxjs throttle
These operators all limit how often values pass through, but they pick different values at different times.

debounceTime(300): waits until the source has been quiet for 300 milliseconds, then emits the last value. If values keep coming, it keeps waiting. Perfect for search boxes: only search after the user stops typing. The downside: during continuous activity, nothing is emitted.

throttleTime(300): emits the first value immediately, then ignores values for 300 milliseconds, then lets the next one through. Good for things like button clicks, to prevent double submits, or for scroll events where you want an immediate reaction and then regular updates. With the config { leading: true, trailing: true }, it also emits the last value at the end of the window.

auditTime(300): when a value arrives, waits 300 milliseconds, then emits the most recent value. So during continuous activity it emits regularly, with the latest value, not the first. Good for things like window resize or drag positions, where you want the latest state at a steady rate.

sampleTime(300): emits the most recent value every 300 milliseconds on a fixed timer, regardless of when values arrived, and only if there was a new value. Good for periodically sampling a fast-changing stream, like progress or sensor readings, for display.

A simple way to remember: debounce waits for silence; throttle takes the first and ignores the rest for a while; audit takes the last after a delay; sample checks on a clock.

Choosing the right one makes the UI feel responsive without flooding the server or the rendering.
