@p4-5
A decision I'm proud of was the design of our CSV bulk import for clinical study data. A study here means one clinical trial set up in our IRT system, with its protocol rules, countries and sites, treatment arms, visit schedule, drug kits and user roles.

So the situation was, study teams wanted to upload large CSV files instead of entering data one record at a time. The big question was, if some rows are bad, do we save the good rows, a partial import, or nothing at all?

I owned the design, so I weighed both options. Partial imports feel friendlier, but in a GxP system they leave a study half-configured, they make rollback and the audit trail messy, and users have to work out what got saved. All-or-nothing is safer, but frustrating if users only find errors at the end.

So I proposed a two-step design. A validate-only preview that checks every row and shows all errors with row numbers, and then an all-or-nothing save in one transaction, but only once the file is clean. I walked the BA and the QA lead through the pros and cons and we agreed on it.

In the end, it's live in production, users fix every error before saving, and we've never had a half-imported study. I can go into the technical design too.

@p4-6
A good example is our SFTP integration for vendor file exchange.

Right, so the situation was, all our vendor file transfers were tied to one SFTP library, ComponentPro. In [2024] a depot vendor hardened their server security, and our connection broke. Because the library calls were spread across the code, switching libraries was risky.

My task was to fix it, and to make sure a library change would never touch business code again.

What I did was introduce a common ISftpClient interface for connect, upload, download and list, with a factory that picks the provider for each vendor from configuration. I added a base class for the shared parts like retries, timeouts and logging. Then I implemented three providers behind it, ComponentPro, SSH.NET and Rebex, and moved vendors over one at a time by configuration, checking each one in UAT first.

In the end, Rebex went to production with [no failed transfers caused by the switch], no business code changed, and a future library change is now one class plus a config entry.

It's honestly a nice real example of the open-closed principle and the strategy pattern.
