@p1-40
Q: WCF (Windows Communication Foundation) is the .NET Framework framework for building service-oriented applications over SOAP and other transports. Every endpoint has ABC: Address (where), Binding (how: transport, encoding, security, such as basicHttpBinding or netTcpBinding) and Contract (what: the [ServiceContract] interface).
- Bindings choose protocol and features: BasicHttpBinding (SOAP 1.1, interop), WSHttpBinding (WS-Security, reliable sessions), NetTcpBinding (fast .NET to .NET), NetNamedPipeBinding (same machine).
- Contracts: ServiceContract, OperationContract, DataContract/DataMember, FaultContract for typed errors.
- Behaviours configure throttling, instance mode (PerCall, PerSession, Single) and concurrency.
- Hosting: IIS/WAS, Windows service or self-host; heavy XML configuration in web.config.
- Modern status: no WCF server in .NET 5+, CoreWCF provides a community port; clients still work via System.ServiceModel packages.
- In IRT older areas still expose WCF endpoints that we maintain and integrate with.
? What is a FaultContract? :: A typed SOAP fault the service declares so clients can handle specific errors.
? PerCall vs PerSession? :: PerCall creates a service instance per request (scalable); PerSession keeps one per client session (stateful).
