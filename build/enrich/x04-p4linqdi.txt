X: These three collection interfaces build on each other, each one adding more abilities.
X: IEnumerable is the simplest. It only lets you loop over items, forward only, and it supports deferred execution. X: Okay, so these four LINQ methods all return one element, but they behave differently when there are zero or multiple matches.

X: The Liskov Substitution Principle says that objects of a derived type should work anywhere the base type is expected, without the caller getting surprises. A subtype can add behaviour, but it has to keep the base type's promises.
X: The textbook violation is Square inheriting from Rectangle. If code sets the width of a rectangle and expects the height to stay the same, a Square breaks that expectation. X: In my SFTP component, Liskov was a real design goal. All three providers implement ISftpClient, and they have to behave the same way for the caller, same behaviour when a file already exists, same timeout handling, and every failure surfaces as our own SftpTransferException, never a silent failure or a library-specific exception. I enforced that with a shared set of contract tests that every provider has to pass.
X: Honestly, that's why we could switch a vendor from ComponentPro to Rebex with only a configuration change. I can explain the contract tests if useful.

X: When an exception happens inside an async method, it doesn't crash straight away. It's captured and stored inside the Task that the method returns.
