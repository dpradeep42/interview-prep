X: A flaky test is basically a test that sometimes passes and sometimes fails, without any change to the code. It's harmful because it destroys trust in the test suite. When tests fail randomly, people start rerunning builds and ignoring failures, and then they miss real bugs.
X: The usual causes are timing issues in asynchronous code, like fixed sleeps, or not waiting for something to finish, shared state between tests, where the order they run in matters, dependence on the real time, time zones or random values, reliance on external services or the network, and in UI tests, not waiting for elements properly.
X: To handle them, I identify them before anything. CI test history shows which tests fail intermittently. Then I don't ignore them.
